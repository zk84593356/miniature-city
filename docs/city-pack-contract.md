# 真实城市包扩展合同

“微缩城市图志”面向真实城市，不使用虚构城市替代。当前深圳使用 `legacy-runtime-v1` 适配器完整保留既有 3D 表现；未来新增大理等城市时，城市资料、授权记录和运行入口必须作为独立城市包登记。

## 目录合同

```text
public-site/
  cities/
    registry.json
    shenzhen/manifest.json
    dali/manifest.json        # 未来
  assets/
  data/
  audio/
```

`cities/registry.json` 只保存平台级索引和默认城市。每个 `manifest.json` 至少包含：

- 稳定城市 id、中英文名称、国家/地区代码；
- 投影类型、原点与世界单位；
- runtime adapter、入口 bundle 与可选动态 chunk；
- 城市数据根目录和音频根目录；
- 行政区列表；
- 每个数据源的名称、URL、许可证与快照日期；
- 应用、模型、音频与数据的授权状态。

## 深圳现状

- `shenzhen` 是默认城市。索引和清单中的资源路径相对于各自 JSON 文件，可以在根路径或由托管层映射的任意子路径下解析到同一城市包。
- 适配器为 `legacy-runtime-v1`；它仍由现有 bundle 读取固定的深圳数据文件。
- 公开版生成器只生成一套与路径前缀无关的根目录产物。运行时数据、音频和动态模块请求相对于入口模块解析；数据内容、二进制格式和 WebGL 参数不变。
- 因此城市 manifest 目前是权利与扩展合同，不是假装已经完成的通用热切换器。

## 新增大理的正确步骤

1. 选择可公开使用的道路、建筑、水系、地形、行政区与地标来源，并保存许可和快照证据。
2. 生成大理专属数据目录；不要覆盖深圳数据文件。
3. 为大理实现新的 runtime adapter，或把现有运行时逐步抽成可配置的通用 renderer。
4. 在 `cities/dali/manifest.json` 登记投影、资源、区域、入口和权利信息。
5. 在 registry 增加大理，但只有在数据闭包、离线、路由、可见浏览器和版权门全部通过后才标记为 `available`。
6. 深圳回归门必须同时运行，避免多城市改造破坏现有 3D 效果。

## 不允许的捷径

- 不得把深圳文件改名后冒充另一城市。
- 不得让两个城市共用会被后续构建覆盖的固定 hash 文件名。
- 不得把来源不明的在线模型、图片或音频直接放入城市包。
- 不得为了抽象化而改变深圳现有相机、Shader、昼夜、交通或数据解码行为，除非新旧运行门同时证明等价。
