# Step 1 开工评级（范围确认前草案）

## 架构结论

- 视觉主体：单页 WebGL 城市全景，three.js 命令式渲染；DOM 是叠加式操作界面。
- 行为事实来源：客户端主包中的命令式类、内联 shader、相机补间和时间/天气参数；地形、交通、城市实例等几何来自 JSON 与自定义二进制资产。
- bundle 形态：Vite 风格、单主包、vendor 与应用逻辑 scope-hoist 拼接；无公开 sourcemap。M1 应先做 chunk/声明普查，再决定直接以原件为坐标或钉版本 beautify。
- DOM 生成方：静态 HTML 外壳 + 客户端脚本生成界面，预计采用静态单页外壳策略。
- 路由形态：当前证据只显示根路径单页；M0 必须用真实浏览器网络补录验证是否还有隐式路由或运行时端点。

## “不要发明”清单

- 不以通用地图或自造低模替代深圳地形、道路、建筑与地标数据。
- 不凭观感调整相机距离、飞行曲线、碰撞高度、昼夜颜色、雾、灯光或后处理参数。
- 不删减 5 个区域、19 个地点、中英文、声音、昼夜、截图、设置、小地图和键盘/触控交互。
- 不把自定义二进制资产手工重画或改成新的数据合同；先还原源合同并建立数值门。
- 不因网络偶发超时而发明资源占位符；缺口必须登记并继续按账本补录。

## 分项难度

| 分项 | 星级 | 证据与理由 |
|---|---:|---|
| 素材获取 | ★★★★ | 同源运行时加载多份地形/建筑/道路/夜景/交通 JSON 与 `.bin`，另有至少两条音频路径；需要 CDP 补录和闭包对账。 |
| 3D/WebGL | ★★★★ | 全市级单场景，但包含地形、建筑实例、道路、水面、昼夜、动态交通、地点模型、相机碰撞与性能降级。 |
| 动画/交互 | ★★★ | 命令式相机飞行、OrbitControls、昼夜切换、城市活动、局部灯光与声音状态机；不是简单静态展示。 |
| 私有格式 | ★★★ | `terrain-buffers`、`traffic-points`、`urban-instances` 等自定义二进制合同需要从读取代码反推并建数值账本。 |
| 平台层 | ★ | 静态 Vite 单页，暂无 CMS/电商/登录平台层；M0 仍需证伪运行时 API。 |
| 素材版权 | ★★★★ | 页面明确使用 OpenStreetMap 与 Mapzen Terrain，另有音频、地标与城市数据来源待逐项取证；公开部署决定尚未作出。 |

## 初步工期量级

- L1 镜像存档：约 0.5–1 个工作日，主要变量是目标站网络稳定性与运行时资产总量。
- L2 工程化复刻：约 2–4 个工作日，主要攻坚点是自定义二进制、动态交通/昼夜与确定性像素门。
- L3 源码化：约 4–7 个工作日，在 L2 全绿后追加声明切片、去混淆命名、注释与自包含验证。

以上为 Step 0/视觉基线后的保守估计；M0 账本和 M1 模块普查会替换其中的未确认项。
